# 流程中心四页完善与验收记录

## 实现范围

- 流程列表、BED、基因列表管理使用完整资源分页读取及每页 20 条展示；资源选择不再截断于前 100 条，支持搜索。新建任务流程选择排除失效自定义资源。
- 组织共享基因列表和报告服务；个人历史资源保持个人身份，创建者或管理员通过“共享到当前组织”显式迁移。服务密钥不返回浏览器，组织管理角色来自 Squid 签名身份。
- 基因符号去首尾空格、大写、去重；名称在准确作用域内唯一。修订版本及 CAS 更新返回 409；描述与疾病分类可清空。浏览器基因筛选固定列表版本，删除或变化不会静默变成全部基因，提供刷新入口。
- BED 上传完成不代表内容可用；校验有两并发、45 秒期限、20 MiB 原始大小、256 MiB 解压上限、200 万行上限。检查完整 gzip、坐标、参考 FAI contig 和边界，保存内容及参考索引 SHA256。基础设施故障标记 unavailable，内容错误标记 invalid，原文件保持不变。
- 仅校验通过 BED 能用于流程、基线和任务。删除与流程/基线/任务引用建立锁定同一资产行；引用冲突返回 409 和可访问的引用摘要。任务保存流程版本及 BED、基线身份/校验快照，重试再次检查。
- “报告服务”保留 /pipeline/templates 路由。report-snapshot-v2 固定 task/attempt、数据集版本、调整版本、成员、样本摘要、QC、仅已回报行和最新解释。原始 Parquet 不修改；置顶不入回报集合，阴性报告保留空数组。
- 生成记录保存服务修订、快照 JSON/hash、操作者、状态及输出对象。clientRequestId 幂等，同一生成固定快照；失败重试不会重新获取后续调整。超时响应不明标为 unknown，避免盲目重复生成。接口限制回报行 <=10000、快照 <=10 MiB、返回文件 <=50 MiB。
- 旧服务标为 legacy-v1，只承诺原始结果包；新版本不依赖旧包准备。HEAD 404/500 失败，405 只说明不支持 HEAD，不认定认证/生成协议验证成功。

## 主要接口及迁移

- 基因列表 update 使用 expected_revision；POST /v1/gene-lists/:id/publish 显式迁移。
- POST /v1/data/assets/:uuid/validate 重新校验 BED。
- 报告服务 update/publish 使用 expectedRevision；新增 contractVersion。
- GET /v1/tasks/:id/report-preview 返回经过同等来源核验的快照摘要，不暴露签名地址或整份注释。
- GET /v1/tasks/:id/report-generations 返回生成记录；原生成接口新增 clientRequestId。
- 新增 report_generations、资源归属/修订/校验字段及任务 pipeline_snapshot_json；名称索引按组织/个人作用域分别建立。保留现有路由和原始结果包。
- 远端部署前核验：历史基因列表 0、报告服务 0、自定义 BED 0，名称冲突 0，无待确认归属迁移记录。

## 验收边界

- 当前没有已配置的外部报告服务，未向任何第三方发送真实医疗资料；真实报告文件生成、对方幂等行为和协议兼容性需配置服务后验证。HTTP/契约路径已用受控测试覆盖。
- 未上传生产 BED 或申请计算实例。内容校验和并发保护有针对性测试；跨用户、跨组织和真实并发数据库压力测试尚需独立验收环境。
- 超过 100 条资源以夹具验收，生产当前只有 4 个内置流程。没有伪造生产资源充数。
- 本轮保留原 Parquet 和现有数据，不申请实例、不重跑工作流，不自动提交 Git。

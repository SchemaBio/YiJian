# 本地初评浏览器基准：首轮结果

这是一份未通过全部门槛的首轮工程报告，不是正式性能验收或临床准确性结论。两个优化开关继续默认关闭。

测量版本为 YiJian `6fffe3578c90bf5774f8982334517bbb3c657fc8`。同一 Windows / Chromium 156 浏览器报告 16 个逻辑处理器、32 GiB device-memory 值；页面保持可见和跨源隔离。硬件字段是浏览器报告值。没有生产接口、患者数据、模型调用或计费流水参与。

基准复用实际 `BrowserTable`、DuckDB/WASM、Parquet 校验和物化、Arrow 流、初评 Worker、候选选择、缓存和排序查询。后端、对象文件和 HPO 回复均为固定合成输入。每种规模包含八类结果以及不参与初评的宽注释列，使用固定的公共 CNV 包并校验摘要。每组五次，p95 使用最近秩法，因此本轮 p95 是五次中的最大值，统计精度有限。两条路径顺序运行，没有同时压测。

冷缓存清除最终初评缓存和已解析 CNV 引用，重建 DuckDB 与初评 Worker；编译产物、系统和 HTTP 缓存可能已热。热缓存保留同一任务、组织和上下文的最终初评缓存，但仍重新授权并重建 DuckDB、打开 Parquet。首次可读为已绘制的只读暂态行或最终首屏；全量时间包含完整初评、Parquet 自动结果物化、首屏排序和绘制。结果摘要计算不在计时及内存采样区间内。

## 测量结果

单位为秒，均为 p95；降低比例按全量完成时间计算。

|---|---|---|---|---|---|
| 10,000 | 冷 | 2.630 / 2.630 | 1.256 / 2.456 | 6.6% | 未达 25% |
| 50,000 | 冷 | 8.700 / 8.700 | 1.726 / 4.265 | 51.0% | 达到本轮时间目标 |
| 100,000 | 冷 | 27.610 / 27.610 | 2.626 / 6.639 | 76.0% | 达到本轮时间目标 |
| 10,000 | 热 | 1.132 / 1.132 | 1.169 / 1.169 | -3.3% | 未达 50% |
| 50,000 | 热 | 1.637 / 1.637 | 1.659 / 1.659 | -1.4% | 未达 50% |
| 100,000 | 热 | 2.268 / 2.268 | 2.218 / 2.218 | 2.2% | 未达 50% |

三种规模、两条路径各五组冷热缓存，共 60 次均完成。每个规模的最终逐行结果数组及排序首屏的 SHA256 在所有运行间一致；没有用减少候选、返回未知或提前停止换取时间。本轮只验证首屏排序摘要；Node 大规模等价性用例另行比较全量结果和参考基因顺序。

冷启动首次可读分别改善约 52%、80%、90%。这是独立于全量完成的体验收益，不能用来替代冷启动全量 25% 门槛。暂态列表是基准对真实客户端事件的只读投影，产品工具栏布局仍需单独验证。

## 热缓存瓶颈

缓存查找本身已经很快，10 万行的代表性热运行中仅约 0.02 ms。主要等待在查缓存之前及之后：

- DuckDB Worker/WASM 启动约 730 ms。
- 完整上下文下载和解析约 252 ms；对完整上下文规范化并计算缓存键约 693 ms。
- 初评完成缓存读取后，自动结果导入与首屏查询仍有成本。该次 `assessment_materialize_ms` 为 1,174 ms，其中包含约 959 ms 的上下文、键和缓存步骤，不能将这些嵌套时间重复相加。

因此当前缓存前置主要省掉了 CNV 包加载，尚未解决完整上下文和浏览器查询引擎的等待。后续优先评估经过授权的不可变内容摘要查询，以及让上下文/引用准备与 WASM 启动并行。任何新路径都必须保留组织权限、任务执行批次、规则和引用内容摘要、样本/HPO/家系上下文的失效检查，并继续做逐行等价性回归。

## 内存与验收结论

本轮每 50 ms 记录 `performance.memory` 的实现相关堆计数。它不是主页面加全部 Worker 的可靠总峰值，因此不能据此宣称通过“内存不超过基线 110%”。例如 5 万行冷运行的堆计数最大值为原路径约 298 MB、优化后约 354 MB，存在需要进一步核查的回归信号；不能忽略这一信号，也不能把它直接当成总内存峰值。

总体验收仍未通过：10k 冷启动、全部热缓存目标未达，完整内存门槛和产品表面验证未完成。功能等价和较大规模冷启动的收益已获得实测支持。

## 延迟、失败和取消回归

两条路径另各执行了三种规模、冷热状态下的 150 ms 端点延迟、参考失败、中途取消，共 36 次运行、18 组对照。场景验证全部通过：延迟场景的最终结果和首屏摘要与正常运行一致；参考失败场景继续保留可用结果，但冷热运行都会重新请求参考，没有把降级结果保存为完整缓存；取消后自动结果数为零，暂态预览撤回，原始结果仍可浏览。参考失败时两条路径的最终降级结果也一致。

每个附加场景每组仅一次，用于功能回归，不能作为弱网 p95 结论。延迟模式未模拟带宽下降、丢包或真实云存储；服务故障为隔离服务显式返回 503，没有触及生产。
